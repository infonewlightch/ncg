# 언어별 제공 범위와 번역 절차

선호 언어는 하나이며 화면·콘텐츠·나눔 번역 요청에 사용한다. 콘텐츠가 없는 언어를 선택해도 선호는 보존한다. 제공되지 않은 본문을 제공된다고 표시하지 않는다.

| 종류 | 현재 포함 | 연결·검수 필요 |
|---|---|---|
| 화면 | 한국어·영어·스페인어 및 사전 생성 13개 언어/문자 팩, 748문구 | 생성 번역·스페인어 원어민 검수, 나머지 언어는 공급 가능한 범위에서 자동 번역; 현재 일일 생성 한도에 도달 |
| 교육·퀴즈·소요리 | 다바르 한국어·영어·태국어 원문 | 교회 콘텐츠 검수, 추가 언어 |
| QT 안내 | 한국어·영어·스페인어 주간 초안 | 교회 검수·실제 발행 |
| 성경 원문 | 영어 WEBP 66권 및 eBible/getBible 제공 역본 | 개역개정 사용허가·본문 공급, 언어별 권리와 실제 본문 검증 |
| 나눔·채팅 번역 | Netlify 공급자·접근 권한·이용량 제한·원문 표시 | 실제 두 계정 통합 검증, 번역 품질 검수 |

7,867개 언어 색인은 언어를 선택할 수 있는 범위다. 번역 완료 개수로 사용하지 않는다. UI 자동번역에 성경 본문을 보내지 않는다. 별도 성경 참고 번역은 공개 영어 WEBP를 사용하며 권위 있는 역본과 명확히 구별한다. 사전 생성 팩과 런타임 구조는 [화면 번역 문서](interface-localization.md)를 따른다.

## 화면 문구 변경

1. 기존처럼 `t('한국어', 'English')`를 쓴다. 가변 값은 `{number}`처럼 명시하고 번역 후 치환한다.
2. `npm run i18n:extract`로 `src/i18n/source.json`을 갱신한다.
3. 등록된 모든 언어 팩에 새 문구를 추가한다. 영어 원문을 키로 사용하며 변수 이름과 개수를 보존한다.
4. `npm run i18n:check`, `npm test`, `npm run build`를 실행한다.
5. 해당 언어로 주요 화면·모달·오류·빈 목록·모바일 레이아웃을 확인한다.

새 언어는 `core/interface.ts` 팩, `core/model.ts`의 UI 언어 타입, `core/languages.ts`의 지원 언어 선택과 테스트를 함께 갱신한다. RTL 언어는 방향을 지정하고 아이콘·문장 내 수치·선택창을 실제 화면에서 검증한다.

카탈로그는 정적 문구와 현재의 `ko/en` 쌍 데이터, 성경 책 이름을 수집한다. 임의의 동적 문구를 자동으로 증명하지는 못하므로 신규 동적 호출은 추출 목록과 대조한다. 빌드 통과는 번역의 신학적·언어학적 검수를 뜻하지 않는다.

공식 고유 명칭 NCG, NEWLIGHT CHURCH GLOBAL, NCG SCHOOL과 대표 슬로건은 브랜드 원문을 유지한다. 날짜·언어명은 선택한 UI 언어로 표시하며 교육 또는 성경이 다른 언어이면 해당 콘텐츠 언어를 분명히 표시한다.
