# 화면 언어 파일 로딩 오류 수정 — 2026-09-25

사용자는 PC 웨일·크롬에서 포르투갈어/중국어 등 메뉴·전체 UI가 전환되지 않는다고 보고했습니다. 기존 운영 화면의 IAB에서는 두 언어가 정상 전환됐고 해당 정적 파일은 HTTP 200이었습니다. 사용자 실제 브라우저 문제와 동일한 원인이라고 확정하지는 않습니다.

재현한 결함은 정적 import 거절을 성공처럼 처리해 선택 언어를 변경하고 영어 화면 및 불필요한 모델 번역 요청을 만드는 경로입니다. 무응답 다운로드는 선택 화면을 계속 잠그기도 했습니다.

- 현재 문맥과 전체 748문구를 검증한 정적 팩만 한 번에 적용합니다. 일부 문구나 문맥이 맞지 않으면 기존 유효 캐시는 보존하고 팩을 거절합니다.
- 파일을 받지 못하면 이전 언어와 선택 창을 유지하며 재시도·새로고침을 제공합니다. 10초 제한과 늦은 응답 격리, 중복 선택 차단을 적용합니다.
- 사전 제작 언어는 네트워크 실패 때문에 생성 API 예산을 사용하지 않습니다. 완전하고 유효한 기기 캐시는 오프라인에서도 사용합니다.
- RED: 신규 회귀 테스트 6개 실패를 먼저 확인. 수정 후 전체 77파일 / 426테스트 및 타입 검사·빌드 통과.
- 실제 IAB 프로덕션 빌드에서 pt 청크에만 503을 반환하는 별도 localhost 서버로 오류 안내·한국어 유지 확인. 파일 공급 복구 → 사용자용 새로고침 → 포르투갈어 전환 성공. 이어 중국어 메뉴·전체 홈 안내도 확인.
- 웨일 현재 화면에서 포르투갈어 UI를 관찰했지만 선택 조작 중 사용자 조작으로 중단됐습니다. Chrome도 사용자 조작으로 중단되어 이번 수정의 두 실브라우저 반복 재현 완료로 기록하지 않습니다.
- 사전 제작 범위는 29종 언어/문자 조합 그대로이며 전 세계 언어 전체 완료가 아닙니다. UI 문구 변경/추가 없음. 성경/영상 본문 번역과 별개입니다.

추가 브라우저 확인: 라오어 UI에서도 QT 날짜가 브라우저 기본 한국어로 표시되는 Intl 미지원 상황을 관찰했습니다. 날짜 포맷에 명시적 영어 대체를 추가해 `10월 5일 — 10월 11일` 대신 `Oct 5 — Oct 11`로 표시됨을 확인했습니다. 지원되는 언어는 기존 현지 날짜 표기를 유지하며, 공동 읽기 날짜/달력은 Gregorian·UTC 계산 그대로입니다. 변경 후 QT 8테스트와 타입 검사·빌드가 통과했습니다.
